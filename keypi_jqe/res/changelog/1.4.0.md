# KeyPi-JQE Changelog

## Version 1.4.0 (2026-01-26)

### Query History Feature

**Major Features:**
- Query History - recall recent JQL queries with `#history`
- `#history clear` to delete all history entries
- Persistent storage (survives Keypirinha restarts)
- Configurable max entries (default: 30)
- Duplicate queries automatically move to top

**Workflow:**
1. **View History**:
   - Type `jqe` → `#history` → List of recent queries appears
   - Select query → `Enter` → Query executes

2. **Clear History**:
   - Type `jqe` → `#history clear` → `Enter` → All history deleted

**Configuration:**
```ini
[main]
# Maximum number of history entries (default: 30)
history_max_entries = 30
```

**Technical Implementation:**
- New `ITEMCAT_HISTORY` category for history items
- History stored in JSON file: `%APPDATA%\Keypirinha\User\keypi_jqe_history.json`
- Format:
  ```json
  {
    "version": 1,
    "queries": [
      {"query": "assignee = currentUser()", "last_used": "2026-01-26T14:30:00"}
    ]
  }
  ```
- History methods: `_load_history()`, `_save_history()`, `_add_to_history()`, `_clear_history()`
- Query added to history after successful execution

**UX Improvements:**
- `#history` shows in the `#` shortcut list
- `#history clear` also available in shortcut list
- History entries show last used date
- Graceful handling of corrupted history files

**Test Coverage:**
- 21 unit tests for history functionality
- Tests for: file parsing, duplicate handling, file operations, clear, input detection

**Benefits:**
- Quick access to recent queries
- No need to remember complex JQL syntax
- Persistent across restarts
- Configurable history size

**Breaking Changes:**
- None - fully backward compatible

---

**Upgrade Notes:**
- Add `history_max_entries` to your config if you want to customize the limit
- History file is created automatically on first query execution
